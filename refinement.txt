1. The shared state schema — the data structure that the orchestrator maintains and every agent reads from / writes to. This is the backbone. If two people define "project state" differently, nothing works.
2. The agent interface contract — every agent, regardless of what it does, must conform to the same input/output interface. The orchestrator shouldn't need to know the internals of any agent — it just calls them through a standard interface and gets structured results back.
3. The tool interface — tools are shared across agents. They need a single, consistent implementation that any agent can use.

Track 1 — Orchestrator + Shared State
Track 2 — Research Phase Agent(s)
The conversational agent that talks to the user, asks clarifying questions, and outputs a structured specification. This person takes your current single-agent's clarification logic and refactors it into a standalone agent that conforms to the new interface. The output is a well-defined spec object (entities, relationships, endpoints, database choice, auth requirements).
Track 3 — Planning Agent + Template System
Takes the structured spec from research and produces a file-by-file implementation plan. This person also improves the template system — making it more flexible, supporting different project archetypes, and ensuring the planning agent can select and customize templates intelligently. The output is a task manifest: which files to create, in what order, with what contents.
Track 4 — Implementation Agents (Code Generation)
This is the biggest track. This person builds the specialist agents that actually write code: the database agent (models, migrations), the API agent (routes, schemas, services), and the scaffold agent. Each one follows the same agent interface but has its own system prompt and scoped tool access. They execute tasks from the plan manifest one by one.

Track 5 — Validation Pipeline + DevOps
The feedback loop that makes everything reliable. This person builds the validation agent (runs linting, type checks, tests after code generation), the error recovery loop (capture failure → feed back to implementation agent → retry), Docker orchestration improvements, and the git commit strategy with proper metadata. This track also handles integrating pytest test generation into the build flow.
